# Contributing

1. Создать issue с целью и критериями.
2. Создать `feature/<short-name>`.
3. Сделать несколько осмысленных коммитов.
4. Запустить `make verify` — должен пройти полностью.
5. Открыть PR (в описании — вывод `make verify`).
6. Получить review второго участника.
7. Исправить замечания.
8. Merge в `main`.

Нельзя коммитить `.env`/секреты, удалять тесты, отключать проверки или пушить незавершенную работу напрямую в `main`.

Первая принятая версия: `v0.1.0`.

## Правила проверок

Эти правила проверяются автоматически (`make policy` — первый шаг `make verify`,
а также хуки в `tests/conftest.py`):

1. **Пропуск тестов запрещён.** Нельзя использовать `@pytest.mark.skip`,
   `skipif`, `xfail`, `pytest.skip()`, `pytest.importorskip()`. Если тест
   пропущен или помечен xfail, прогон завершается ошибкой.
2. **Пороги не снижаются.** Минимальное покрытие — `fail_under = 85` в
   `pyproject.toml`, нижняя граница зашита в `scripts/check_policy.py`
   (`MIN_COVERAGE`). В `Makefile` и `addopts` запрещены `--cov-fail-under`,
   `--no-cov`, `--deselect`, `--ignore`.
3. **Исключения анализаторов — только с обоснованием.** Каждый
   `# noqa`, `# nosec`, `# pragma: no cover`, `# type: ignore` должен содержать
   пояснение после `--`, например:
   `from app import models  # noqa: F401 -- импорт регистрирует модели`.
   Для bandit пояснение отделяется вторым `#`: `# nosec B603 # -- причина`.
   Исключения в конфигурации (`[tool.ruff.lint] ignore`) тоже комментируются.
4. **Эквивалентные мутанты** помечаются `# no-mutate -- причина` только если
   изменение действительно не меняет поведение программы.
5. Любое изменение порогов, правил линтера или этих правил делается отдельным
   PR с обоснованием и одобрением второго участника.
