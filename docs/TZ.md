# Техническое задание

## 1. Наименование
Информационная система учета аукционов.

## 2. Назначение
Учет аукционов, лотов, продавцов, покупателей, ставок и результатов продаж.

## 3. Пользователи
Оператор/администратор, продавец, покупатель, разработчик/эксплуатационный инженер учебного контура. В первой версии аутентификация не реализуется.

## 4. Сценарии
1. Создать аукцион.
2. Добавить продавца и покупателя.
3. Создать лот (только для аукциона в статусе PLANNED или ACTIVE).
4. Запустить аукцион.
5. Разместить несколько ставок.
6. Отклонить ставку, не превышающую текущую максимальную.
7. Оформить продажу лота: оператор явно указывает покупателя и цену; продажа закрывает лот (переводит в SOLD).
8. Просмотреть продажи и выручку.
9. Завершить или отменить аукцион; все непроданные лоты (AVAILABLE) при этом автоматически переходят в UNSOLD.

## 5. Требования
HTTP API + web UI; PostgreSQL; Alembic; конфигурация через окружение; health endpoint; понятные ошибки; тестируемость; Git workflow.

## 6. Бизнес-правила
- лот можно добавить, изменить или удалить только для аукциона в статусе PLANNED или ACTIVE;
- ставка принимается только для лота AVAILABLE на ACTIVE аукционе;
- сумма ставки строго больше текущего максимума (или стартовой цены, если ставок ещё нет);
- продажа создаётся явно (покупатель и цена указываются оператором), возможна только для лота AVAILABLE на ACTIVE аукционе, цена не ниже стартовой;
- создание продажи закрывает лот (SOLD); повторная продажа запрещена;
- при завершении или отмене аукциона непроданные лоты (AVAILABLE) переводятся в UNSOLD;
- аукцион с существующими лотами нельзя удалить; лот со ставками нельзя удалить;
- выручка вычисляется как сумма цен продаж.

## 7. Ограничения Lab 1
Не реализуются заранее полноценная аутентификация, reverse proxy, масштабирование, мониторинг, централизованные логи, CD, Ansible и другие механизмы следующих лабораторных.
